# 桌面端说明

桌面端是**端侧离线**的原生客户端：业务引擎、数据库与材料生成全部在本机完成，不需要服务器、不产生外部请求。

- 技术栈：Avalonia UI 12 + .NET 10，复用现有 `Domain / Application / Infrastructure / AI / Documents / ProjectScan` 引擎
- 首期平台：**Windows、macOS、Linux**（macOS / Linux 产出可编译工程，签名产物需在对应机器上打包）
- 后续平台：Android、iOS（同一套 Avalonia 工程加移动端目标）；**鸿蒙本期不做**（鸿蒙 NEXT 没有 .NET 运行时，需要独立 ArkTS 工程与签名链，风险与工期都不可控）

---

## 一、为什么引擎能直接搬到桌面端

搬之前先确认过一件事：**业务引擎本来就不依赖 ASP.NET**。

| 项目 | 依赖 | 结论 |
|---|---|---|
| `SoftCopyright.Domain` | 仅 BCL | 可直接复用 |
| `SoftCopyright.Application` | Domain | 可直接复用 |
| `SoftCopyright.Infrastructure` | Domain + Application（含 EF Core、SQLite、文件存储、后台任务） | 可直接复用 |
| `SoftCopyright.AI` / `Documents` / `ProjectScan` | Domain | 可直接复用 |
| `SoftCopyright.Api` / `SoftCopyright.Web` | ASP.NET Core / Razor | **只有这两层是 Web 专属**，桌面端不需要 |

用例服务本身也不依赖 HTTP 契约：

- `ICaseUploadService.UploadAsync(caseId, fileName, Stream, ct)` —— 收的是流，桌面端直接 `File.OpenRead` 即可
- `ICurrentAccountContext.Use(userId)` —— Web 端由中间件写入，桌面端由组合根写入
- `ISecretProtector` / `IPasswordHasher` —— 密钥文件与密码派生都在本机，不变

所以桌面端不是"把 Web 再写一遍"，而是**换一个宿主**：把引擎装进本机进程，把 Web 的 HTTP 边界换成进程内调用。

## 二、桌面端与 Web 端的差异

| 关注点 | Web 端 | 桌面端 |
|---|---|---|
| 数据库 | MySQL（服务器） | 本机 SQLite（`%LOCALAPPDATA%\SoftCopyright\softcopyright.db`） |
| 账号 | 注册 / 登录 / Cookie | 单用户：内置管理员账号，案例全部归属它，界面没有登录页 |
| 调用方式 | 界面 → HTTP → API → 用例 | 界面 → 视图模型 → **直接调用**用例 |
| 数据目录 | 服务器上的 `Storage:DataRoot` | 本机 `%LOCALAPPDATA%\SoftCopyright`（可用 `SOFTCOPYRIGHT_DESKTOP_DATA_ROOT` 覆盖） |
| 模型接入 | 账号级配置 + 全局环境变量 | 同一套账号级配置（密钥加密后存本机库），不配就是完全离线 |
| 界面 | Razor / Blazor | Avalonia / MVVM |

校验规则、材料生成器、选项目录这些"业务事实"只有一份，桌面端直接复用，没有第二套实现。

## 三、工程结构

```
src/SoftCopyright.Desktop/
  Program.cs                    # 启动入口：先备好引擎，再启动 Avalonia
  App.axaml / App.axaml.cs      # 主题与设计令牌（深浅双套）
  Themes/Controls.axaml         # 控件样式
  Services/
    DesktopEngine.cs            # 引擎组合根：无 ASP.NET 的 DI + 本机库 + 后台任务
    AppBootstrap.cs             # 启动期共享状态
    ThemeService.cs             # 深浅主题切换与偏好持久化
    DesktopLaunchOptions.cs     # --case / --step / --demo / --snapshot
    DemoSeeder.cs               # 演示数据
    OsLauncher.cs               # 打开本机数据目录
  ViewModels/                   # MVVM（CommunityToolkit.Mvvm）
  Views/                        # 六个步骤视图
```

### 启动顺序（容易踩坑）

引擎必须在 **Avalonia 初始化之前**就绪。在 UI 线程上阻塞等待异步任务会与 Avalonia 的同步上下文死锁：

```csharp
// Program.Main：此时还没有 Avalonia 同步上下文，阻塞等待是安全的
AppBootstrap.Engine = DesktopEngine.StartAsync(args).GetAwaiter().GetResult();
BuildAvaloniaApp().StartWithClassicDesktopLifetime(args);
```

同样地，**先建库再启动后台任务**：后台任务执行器一上来就会查任务表，库还没迁移就会报 `no such table: BackgroundJobs`。

```csharp
var host = builder.Build();
// 先迁移数据库，再 Start —— 顺序反了后台任务会先炸
await DatabaseInitializer.InitializeAsync(db, logger, ct);
await host.StartAsync(ct);
```

### 迁移快照与 SQLite

迁移快照是按 **MySQL** 提供程序生成的（里面记录的是 MySQL 的默认类型映射）。换到 SQLite 后逐项比对必然出现差异——这是提供程序差异，不是真实的结构变更。SQLite 的类型系统更宽松，同一套迁移脚本可以直接套用，因此只在 SQLite 分支关闭了这条告警（`InfrastructureServiceExtensions.ConfigureDatabase`）。

## 四、运行与打包

```powershell
# 开发运行
dotnet run --project src/SoftCopyright.Desktop

# 生成演示案例（用仓库里的样例仓库，含一份示例申请信息）
dotnet run --project src/SoftCopyright.Desktop -- --demo

# 直接打开指定案例的指定步骤
dotnet run --project src/SoftCopyright.Desktop -- --case <案例 ID> --step Applicant

# 把当前窗口渲染成 PNG（文档截图与界面自查用，不受屏幕分辨率影响）
dotnet run --project src/SoftCopyright.Desktop -- --case <案例 ID> --step Applicant --snapshot out.png
```

发布：

```powershell
# Windows（自包含，目标机器不需要装 .NET）
./scripts/publish-desktop.ps1 -Platform windows

# Windows 安装包（需要本机装有 Inno Setup 6）
./scripts/publish-desktop.ps1 -Platform windows -Installer

# Linux / macOS
./scripts/publish-desktop.ps1 -Platform linux
./scripts/publish-desktop.ps1 -Platform macos
```

产物落在 `artifacts/desktop/<平台>/`（该目录不纳入版本控制）。

macOS 与 iOS 的签名产物必须在 macOS 上用 Xcode 签名；鸿蒙需要 DevEco Studio 与鸿蒙签名证书——两者都不在 Windows 上产出。

## 五、界面

六个步骤：案例 → 导入仓库 → 分析与证据 → 申请信息 → 代码材料 → 材料与导出。

- **深浅双主题**：设计令牌与 Web 端同一套语义，`App.axaml` 里用 `ThemeDictionaries` 给两套取值，切换即时生效并记在本机 `ui-preferences.json`
- **申请信息页**按官方申请表的分区排布；八个官方规定选项渲染为下拉，候选项直接来自 `ApplicantOptionCatalog`（不在界面里硬编码）
- **条件字段**紧跟触发它的选项：选了「修改软件」就出现「修改说明」，选了「已发表」就出现「首次发表日期 / 地点」；「原始取得 + 非单独开发」的冲突会在开发方式下方直接提示

## 六、测试

`tests/SoftCopyright.Tests/Integration/DesktopEngineTests.cs` 直接驱动 `DesktopEngine`，验证**没有 ASP.NET、没有 HTTP** 的情况下整条链路能跑通：

- 端侧引擎在不启动服务器的情况下跑通完整软著闭环（新建 → 导入 ZIP → 扫描 → 分析 → 确认画像 → 填申请信息 → 确认 → 选代码 → 确认 → 生成材料 → 读出材料包）
- 端侧引擎拒绝不在候选项之内的申请信息
- 端侧引擎拒绝格式非法的分类号
- 无服务器时仍能解析本机账号与模型接入状态（未配置密钥时必须是完全离线）
- 启动参数能指定案例与步骤
- 演示数据能生成带样例申请信息的案例

## 七、已知边界

- **鸿蒙本期不做**。鸿蒙 NEXT 不支持 .NET 运行时，也不能装 Android APK；要做只能另起 ArkTS 工程并重写引擎，工作量与签名链风险都不可控。后续如需覆盖，建议评估 ArkUI-X（复用 Android 构建）。
- **iOS 未在本期交付**。Avalonia 的 iOS 后端可用，但需要在 macOS 上签名与打包，本机（Windows）无法产出可安装包。
- **桌面端当前只覆盖软著线**。专利线在引擎层已经就绪（`PatentMaterialFlow` 等），但界面尚未实现，需要补「专利交底书」与「专利材料」两个步骤。
- **迁移快照以 MySQL 为准**。桌面端用 SQLite 跑同一套迁移；如果以后要支持其他提供程序，需要单独一套迁移程序集。
- **桌面端是单用户**。没有登录页与多账号隔离；需要多人协作时仍应使用 Web 端。
