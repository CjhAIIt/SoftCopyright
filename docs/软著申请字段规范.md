# 软著申请字段规范

本文件说明「申请信息」页各字段的类型约定：**哪些字段在官方申请表里本来就是选项、哪些是自由文本、选项之间有哪些联动要求**。

> **依据**：中国版权保护中心《计算机软件著作权登记申请表填写说明》。
>
> **声明**：本文件与项目内的实现（`ApplicantOptionCatalog`）是**工程实现，不是官方权威解释**。
> 官方对本说明具有最终的解释权和修改权，材料中一律提示申请人按官方最新要求核对。

---

## 一、为什么要做这件事

在引入选项目录之前，「申请信息」页里的开发方式、权利取得方式、发表状态等字段都是自由文本框，
申请人可以填「独立开发」「自己开发的」「原创」等任意写法。这类写法有两个问题：

1. **提交口径不统一**：同一份权利关系在不同案例里被写成不同字符串，材料之间无法互相核对；
2. **无法表达官方写明的联动规则**：例如「软件著作权为原始取得的，申请登记的软件须为独立开发」，
   以及「选择已发表的，请填写首次发表日期和首次发表地点」——这些规则用自由文本表达不出来。

因此把官方规定为选项的字段收敛成**受约束的候选项**，把联动规则表达成**数据**（条件必填、取值约束），
并由前端按数据渲染下拉、后端按数据校验。

---

## 二、选项型字段（8 个）

选项目录定义在 `src/SoftCopyright.Domain/ApplicantOptionCatalog.cs`，
通过 `GET /api/softcopyright/applicant-options` 下发给前端，前端不硬编码任何候选项。

数据库里存的是**规范选项码**（稳定的英文标识），显示文本由选项目录解析。
这样官方措辞调整时只需改一处标签，历史数据的含义不会漂移。

| 字段（申请表栏位） | 属性名 | 规范选项码 → 显示文本 |
|---|---|---|
| 软件来源 | `SoftwareSource` | `Original` 原创软件<br>`Modified` 修改软件<br>`ModifiedAuthorized` 修改软件须经原权利人授权 |
| 开发方式 | `DevelopmentMode` | `Solo` 单独开发<br>`Cooperative` 合作开发<br>`Commissioned` 委托开发<br>`AssignedTask` 下达任务开发 |
| 发表状态 | `FirstPublicationStatus` | `Published` 已发表<br>`Unpublished` 未发表 |
| 权利取得方式 | `RightsAcquisitionMethod` | `OriginalAcquisition` 原始取得<br>`Assignment` 继受取得—受让<br>`Inheritance` 继受取得—继承<br>`Assumption` 继受取得—承受 |
| 权利范围 | `RightsScope` | `All` 全部权利<br>`Partial` 部分权利 |
| 著作权人类别 | `OwnerType` | `NaturalPerson` 自然人<br>`LegalPerson` 法人<br>`UnincorporatedOrganization` 非法人组织<br>`Other` 其他 |
| 申请办理方式 | `ApplicationHandlingMethod` | `ByOwner` 著作权人申请办理<br>`ByAgent` 代理人申请办理 |
| 鉴别材料交存方式 | `DepositMode` | `General` 一般交存<br>`ExceptionMasked` 例外交存 a：源程序前后各 30 页，机密部分遮盖<br>`ExceptionPages` 例外交存 b：源程序连续前 10 页 + 任意连续 50 页<br>`ExceptionTarget` 例外交存 c：目标程序前后各 30 页 + 源程序任意连续 20 页 |

### 别名归一化

选项目录为每个候选项登记了**历史写法别名**。旧案例里已经填了「独立开发」「原始取得」「受让」，
这些写法会被归一化到规范选项码，不会因为升级而失效或变成非法值：

```
ApplicantOptionCatalog.Normalize("DevelopmentMode", "独立开发") → "Solo"
ApplicantOptionCatalog.Normalize("RightsAcquisitionMethod", "受让") → "Assignment"
```

无法归一化的写法（例如「自己写的开发方式」）在保存时会被直接拒绝（HTTP 400）。

## 三、条件必填规则

以下规则来自官方填写说明中的联动要求，表达为 `ApplicantCondition`：

| 触发字段 | 取值 | 联动必填字段 | 官方依据 |
|---|---|---|---|
| 软件来源 | 修改软件 | 修改说明 | 软件为修改版本的，应选择「修改」并填写修改说明 |
| 软件来源 | 修改软件须经原权利人授权 | 修改说明 | 同上 |
| 权利取得方式 | 继受取得—受让 / 继承 / 承受 | 原登记号 | 该申请软件若是已做过著作权登记的，需填写原登记号 |
| 权利范围 | 部分权利 | 部分权利权项说明 | 部分权利需注明具体的权项 |
| 发表状态 | 已发表 | 首次发表日期 | 软件已发表的，请选择已发表选项，并填写首次发表日期 |
| 发表状态 | 已发表 | 首次发表地点 | 软件已发表的……并填写首次发表地点 |

界面上这些字段会**随选项联动出现**，并自动带上必填标记；材料生成时同样按联动结构输出。

---

## 四、跨字段取值约束

| 触发字段 | 取值 | 相关字段 | 允许取值 | 官方依据 |
|---|---|---|---|---|
| 权利取得方式 | 原始取得 | 开发方式 | 单独开发 | 软件著作权为原始取得的，申请登记的软件须为独立开发 |

界面会在检测到冲突时直接给出提示（例如「当前「开发方式」应选择：单独开发」），
校验报告也会把它列为需处理项。

## 五、自由文本字段

这些字段按官方要求由申请人自行填写，系统不预填、不推断：

| 栏位 | 属性名 | 填写要求 |
|---|---|---|
| 软件全称 | `SoftwareFullName` | 简短明确、针对性强；不得以「工具」「计算」「系列」等结尾；与鉴别材料页眉保持一致 |
| 软件简称 | `SoftwareAbbreviation` | 没有简称请留空，不要填「无」；不得与软件全称完全相同 |
| 版本号 | `VersionNumber` | 建议 `V1.0` 或 `1.0`；鉴别材料页眉的版本号应与申请表一致 |
| 分类号 | `ClassificationCode` | GB/T 13702 软件分类代码（5 位）+ GB/T 4754 国民经济行业分类代码（4 位），形如 `12345-1234`；**格式不符时拒绝保存** |
| 著作权人 | `CopyrightOwner` | 姓名或名称如实填写 |
| 开发完成日期 | `CompletionDate` | 将软件全部固定在有形载体上的日期 |
| 首次发表日期 | `FirstPublicationDate` | 见条件必填 |
| 首次发表地点 | `FirstPublicationPlace` | 见条件必填 |
| 修改说明 | `ModificationDescription` | 见条件必填 |
| 原登记号 | `OriginalRegistrationNumber` | 见条件必填 |
| 部分权利权项说明 | `PartialRightsDescription` | 见条件必填 |
| 硬件环境 | `DevelopmentEnvironment` | 机型及 CPU 等 |
| 软件环境 | `RuntimeEnvironment` | 操作系统、支持软件的名称及版本号 |
| 编程语言 | `ProgrammingLanguages` | 编写登记软件的编程语言及版本号 |
| 源程序量 | `SourceProgramAmount` | 程序量，用于与材料中的实际代码行数交叉核对 |
| 功能简介 | `FunctionSummary` | 开发目的、面向领域/行业、主要功能、技术特点；官方对本栏有字数上限要求，请按官方最新要求核对 |

## 六、校验落在哪一层

| 层 | 行为 | 代码位置 |
|---|---|---|
| 保存（服务层） | **值域非法**或**分类号格式非法**直接拒绝（400）；**尚未选择**的选项允许留空，表单可以先存草稿 | `ApplicantInfoService.NormalizeOption` / `Validate` |
| 确认（校验规则集） | 新增规则 `R-FIELDS-02 选项字段合规性`：必选项未选、条件必填未满足、跨字段冲突、格式非法，均列为「需申请人处理」 | `SoftCopyrightValidationRuleSet.CheckOptionFields` |
| 生成（材料） | 申请表信息与申请信息草稿按官方分区输出，选项显示为官方中文标签 | `MaterialDocumentGenerator` |

服务层与校验规则集**共用同一份判定**（`ApplicantOptionChecker`），
保证界面提示、接口拒绝和校验报告的口径一致，不会出现「界面说过了但报告说没过」。

---

## 七、已知边界

- 官方对「主要功能和技术特点」等栏目的字数上限会调整，本工具**不内置字数上限**，
  只在界面上提示按官方最新要求核对。
- 鉴别材料的实际页数、每页行数由代码材料规则（`MaterialRules.CodeMaterial`）控制，
  与交存方式的例外交存要求并不完全等价，材料中如实报告实际页数，不做粉饰。
- 选项目录覆盖的是**申请表栏目**层面的规定；证明文件（合作协议、委托协议、授权书等）
  需要申请人自行准备，本工具不生成、不校验其存在性。
