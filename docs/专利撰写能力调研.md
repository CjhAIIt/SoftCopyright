## 二、共识与本项目的差异化定位

社区项目的共同点与警示：

1. **AI 只做初稿辅助**。权利要求保护范围、新颖性、创造性必须由专利代理人复核——这是所有项目的共同声明。
2. **单一真源工作流**。以"技术交底书"为唯一输入，向下派生摘要、权利要求书、说明书，避免多处改写导致口径不一致。
3. **权利要求必须有说明书支持**（引用基础 / 支持性），是自检的第一优先级。
4. **编号与引用关系必须自洽**：独立权利要求在前，从属权利要求引用在前序号。
5. **禁止编造现有技术**：对比文件必须可溯源。
6. **充分公开**：至少多个实施例，且描述要与实现一致。

### 本项目的独特优势

社区项目多以"技术交底书（docx）"或"论文"为输入；而本工具**天然拥有可回溯的代码证据链**（相对路径 + 行号 + SHA-256）。因此可以实现社区项目普遍做不到的一点：

> **专利技术特征直接锚定到源码事实**：凡描述算法、数据结构、阈值、参数之处，必须指向仓库中的具体文件与行；无证据支撑的特征一律标注"待申请人补充"，不允许模型编造。

这正好把 `cn-patent-drafter` / `repo2patent` 的"援引代码事实"理念，落到可自动校验的工程机制上。

## 三、本项目的选型与取舍

| 能力 | 社区做法 | 本项目做法 | 理由 |
|---|---|---|---|
| 交底书来源 | 人工撰写 docx | **由扫描证据 + 申请人填写生成**，并持久化 | 复用既有证据模型，避免重复录入 |
| 权利要求 | 多智能体/提示词生成 | 规则引擎生成结构 + 模型可选润色，**每条带技术特征与证据引用** | 结构必须确定可校验，措辞才交给模型 |
| 说明书五部分 | 提示词生成 | 规则组装 + 模型润色，章节级引用证据 | 避免"看起来通顺但无依据" |
| 校验 | 检查清单 / MPEP | **并入既有校验中心**（三级结论 + 规则号 + 修复建议） | 复用软著已有的校验框架与报告页 |
| 现有技术检索 | 依赖 BigQuery / EPO / PatentsView | **本期不实现**，仅支持人工填写并标注来源 | 外部 API 配额与稳定性不可控；不编造对比文件 |
| 附图生成 | Graphviz / Mermaid | **本期不实现**，支持附图说明文字与图号引用 | 附图可后续接 Mermaid 渲染 |
| 输出格式 | LaTeX / DOCX | **DOCX**（与软著材料包统一） | 与现有材料生成链路一致 |
| 法域 | CNIPA / USPTO / EPO | **本期只做 CNIPA 风格**（发明 + 实用新型） | 单一法域做扎实，避免"三法域都半成品" |

## 四、风险声明（与社区一致，且必须写进产品界面）

- 本工具产出的是**专利申请文件初稿**，不是可提交的最终文本。
- 权利要求的保护范围、新颖性、创造性、说明书是否充分公开，**必须由专利代理人复核**。
- 本工具不提供现有技术检索结论，不对新颖性作任何判断。
- 材料规则是工程配置，**不是官方权威解释**，须按国家知识产权局（CNIPA）最新撰写规范核对。

## 六、实现过程中发现并修正的问题

1. **证据包丢弃精确摘录**：证据包构建器原先对文档类证据直接取整份文件内容，导致 README 全文被当作"技术特征"写进权利要求书。改为优先使用扫描阶段提取的精确摘录，代码文件才取文件头若干行。
2. **中文候选要素永远匹配不到证据**：原先按空格与标点切分关键词，中文整句被当成一个词，命中率恒为 0。改为中文按二元组切分、英文按词切分，并改用绝对命中数阈值。
3. **权利要求正文写死编号**：从属权利要求正文里硬编码了 `"2. "`，与编号表不一致。改为正文不带编号，编号统一由文档生成器输出。
4. **技术领域措辞重复**：申请人在交底书中已写"本申请涉及……领域"，模板再套一层会得到"本申请涉及本申请涉及……领域领域"。已按内容判断是否需要补模板。
5. **JSON 列超出 MySQL 行长上限**：实施例与技术特征 JSON 曾超过 `text` 列的 65535 字节上限，导致后台任务反复失败重试、表面上表现为"任务卡在 20%"。处理方式有三：生成器侧截断证据原文并标注"完整内容见证据出处"；列类型升级为 `longtext`（新增迁移 `ChangePatentJsonColumnsToLongText`）；后台任务最终失败时把失败原因回写到案例，避免只看到进度停在某个百分比而无从排查。

> 教训：后台任务"长时间停在同一百分比"未必是死锁，更可能是**可重试的失败**。因此最终失败原因必须落到案例的 `FailureReason` 上，工作台才能显示可诊断的信息。
