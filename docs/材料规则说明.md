# 材料规则说明

## 一、规则的性质（重要）

本工具使用的材料规则是**工程配置**，不是官方权威解释。

- 规则集有明确版本号（如 `2026.11-v1`），写入案例记录、校验报告与生成清单；
- 规则内容集中配置在 `appsettings.json` 的 `MaterialRules` 段，**禁止散落硬编码**；
- 所有生成材料都附带固定声明："本工具内置工程配置，非官方权威解释，请按官方最新要求核对"；
- 校验报告只说明"本工具自动化规则的检查结果"，**不代表登记审查结论**。

> 申报人必须自行按中国版权保护中心（或其他主管机构）的最新要求核对后再提交。

## 二、规则集结构

```json
"MaterialRules": {
  "Version": "2026.11-v1",
  "Source": "本工具内置工程配置，非官方权威解释，请按官方最新要求核对。",
  "CodeMaterial": {
    "LinesPerPage": 50,
    "TargetPages": 30,
    "IncludeFileBoundaryMarkers": true
  },
  "Fields": {
    "RequiredFields": ["SoftwareFullName", "VersionNumber", "..."],
    "LegalOnlyFields": ["CopyrightOwner", "DevelopmentMode", "..."],
    "MaxFieldLength": 2000,
    "MaxSummaryLength": 4000
  },
  "Layout": {
    "BodyFontSizeHalfPoints": 24,
    "LineSpacing": 312,
    "ShowPageNumbers": true
  }
}
```

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `CodeMaterial.LinesPerPage` | 50 | 代码鉴别材料每页行数 |
| `CodeMaterial.TargetPages` | 30 | 目标页数；**达不到时如实报告实际页数**，不重复填充、不编造 |
| `CodeMaterial.IncludeFileBoundaryMarkers` | true | 是否在文件边界插入来源标记 |
| `Fields.RequiredFields` | 8 项 | 必填的**自由文本**字段清单（选项型字段的必填性由选项目录决定，不在此重复） |
| `Fields.LegalOnlyFields` | 15 项 | 法律与权属字段，系统永不预填 |
| `Fields.MaxFieldLength` | 2000 | 单字段最大长度 |
| `Fields.MaxSummaryLength` | 4000 | 功能简介最大长度 |
| `Layout.BodyFontSizeHalfPoints` | 24 | 正文字号（半磅，即 12pt） |
| `Layout.LineSpacing` | 312 | 行距（240 = 单倍行距） |

## 四、代码鉴别材料抽取规则

1. 按用户确认的顺序（默认按相对路径字典序）逐文件读取**原始字节**；
2. 按行切分，**保留原始行内容，不做任何改写、补写或格式化**；
3. 每页 `LinesPerPage` 行，页首插入文件边界标记：

   ```text
   // 文件：src/Sample.App/Program.cs（起止行 1-27，SHA-256 3f2a1c9e8b7d6a5f）
   ```

4. 每页标注 `第 N 页 / 共 M 页`；
5. 行数不足时不重复填充、不编造，材料中如实给出实际页数与总行数；
6. 每份文件的 SHA-256 与 `ProjectFile` 记录一致，校验规则 `R-TRACE-01` 会逐个核对。

## 五、校验规则清单

| 规则号 | 检查内容 | 级别 |
|---|---|---|
| `R-FIELDS-01` | 必填字段是否齐全 | 缺字段 → 需申请人处理 |
| `R-FIELDS-02` | 选项字段合规性（必选项未选、取值越界、条件必填未满足、跨字段冲突、分类号格式） | 命中 → 需申请人处理 |
| `R-CONSIST-01` | 案例登记的名称/版本与申请信息是否一致 | 不一致 → 需申请人处理 |
| `R-CONSIST-02` | 填报源程序量与材料实际行数是否一致 | 差异 → 警告 |
| `R-TRACE-01` | 代码文件哈希与仓库原始文件是否一致 | 不一致 → 需申请人处理 |
| `R-FILE-01` | 产物是否存在、可读、非空 | 缺失 → 需申请人处理 |
| `R-RULES-01` | 规则版本是否已记录且与当前配置一致 | 不一致 → 警告 |
| `R-PENDING-01` | 是否仍有未处理的待确认事项 | 命中 → 需申请人处理 |
| `R-SECRET-01` | 是否命中疑似凭据文件 | 命中 → 警告 |
| `R-COVERAGE-01` | 分析覆盖度是否偏低 | 偏低 → 警告 |

三级含义：

- **通过**：本工具的规则检查没有发现问题；
- **警告**：存在需要留意的问题，但不影响材料生成；
- **需申请人处理**：必须由申请人补充或确认后才能形成可提交材料。

> 三级结论都**不表示**登记会通过。
