# 开发指南

面向要在这个仓库上改代码的人：怎么把环境跑起来、每个工程负责什么、常见坑在哪。

---

## 一、环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| .NET SDK | **10.0** | `TargetFramework=net10.0`；`Directory.Build.props` 开了 `TreatWarningsAsErrors`，**0 warning 是硬要求** |
| MySQL | 8.0 | 只有服务端（Web 端）需要；客户端与测试都走 SQLite |
| Git | 任意 | 仅 Git 导入通道需要（只调用 `git` 自身） |
| Node.js | 不需要 | 界面是 Blazor（服务端渲染）与 Avalonia（原生），没有前端构建链 |
| Android SDK | 可选 | 只有要出 APK 时需要；否则 .NET 自带的 Android 打包工具够用 |
| Inno Setup 6 | 可选 | 只有要出 Windows 安装包时需要 |

移动端工作负载（只在要构建 Android 时装）：

```powershell
dotnet workload install android
```

## 二、克隆与还原

```powershell
git clone https://github.com/CjhAIIt/SoftCopyright.git
cd SoftCopyright
dotnet tool restore          # 还原仓库内的 dotnet-ef（dotnet-tools.json）
dotnet build                # 必须 0 error / 0 warning
dotnet test                 # 必须全绿
```

> **注意**：`.gitignore` 里的 `data/` 必须锚定到仓库根目录（`/data/`）。未锚定的 `data/` 在 Windows 上大小写不敏感，
> 会连同 `src/**/Data`（EF 迁移目录）一起被忽略，导致新克隆缺迁移、无法建库。

## 三、数据库

### 服务端（MySQL）

连接串**不进仓库**，用环境变量注入：

```powershell
$env:SOFTCOPYRIGHT_MYSQL = "Server=127.0.0.1;Port=3306;Database=softcopyright;User Id=softcopyright;Password=你的密码;CharSet=utf8mb4;"
```

首次启动会自动建库并跑迁移（`DatabaseInitializer.InitializeAsync` → `MigrateAsync`）。

### 客户端与测试（SQLite）

客户端默认用本机 SQLite，落在：

| 平台 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%\SoftCopyright\softcopyright.db` |
| Linux | `~/.local/share/SoftCopyright/softcopyright.db` |
| macOS | `~/Library/Application Support/SoftCopyright/softcopyright.db` |
| Android | 应用内部存储目录（`FilesDir/SoftCopyright`） |

可用环境变量 `SOFTCOPYRIGHT_DESKTOP_DATA_ROOT` 覆盖（便携部署、测试隔离都用它）。

> **迁移快照是按 MySQL 生成的**：快照里记录的是 MySQL 的默认类型映射，换到 SQLite 后逐项比对必然出现差异——
> 这是提供程序差异，不是真实的结构变更。SQLite 类型系统更宽松，同一套迁移脚本可以直接套用，
> 因此只在 SQLite 分支关闭了 `PendingModelChangesWarning`。若将来要支持别的提供程序，需要单独一套迁移程序集。

### 测试库

```powershell
$env:SOFTCOPYRIGHT_TEST_MYSQL = "Server=localhost;Port=3306;Database=softcopyright_test;User Id=softcopyright;Password=你的密码;CharSet=utf8mb4;"
dotnet test
```

未配置时自动回退到 SQLite 临时库，保证离线也能跑。MySQL 模式下**每个测试宿主使用独立临时库**（`softcopyright_test_<guid>`），避免并行迁移冲突。

## 四、常用命令

```powershell
# 编译（0 error / 0 warning）
dotnet build

# 全量测试
dotnet test
dotnet test --filter "FullyQualifiedName~DesktopEngineTests"   # 只跑端侧引擎
dotnet test --filter "FullyQualifiedName~PatentFlowTests"      # 只跑专利端到端

# Web 端
dotnet run --project src/SoftCopyright.Api                       # http://localhost:5080

# 原生客户端
dotnet run --project src/SoftCopyright.Desktop
dotnet run --project src/SoftCopyright.Desktop -- --demo                       # 生成演示案例
dotnet run --project src/SoftCopyright.Desktop -- --step Applicant              # 打开申请信息页
dotnet run --project src/SoftCopyright.Desktop -- --size 390x844                # 按手机尺寸开窗
dotnet run --project src/SoftCopyright.Desktop -- --step Applicant --snapshot a.png  # 导出界面渲染图

# 发布
./scripts/publish-desktop.ps1 -Platform windows        # 自包含程序
./scripts/publish-desktop.ps1 -Platform windows -Installer  # 附带 Inno Setup 安装包
./scripts/publish-desktop.ps1 -Platform linux
./scripts/publish-desktop.ps1 -Platform macos
./scripts/build-mobile.ps1                           # Android APK

# 数据库迁移
dotnet ef migrations add <名字> --project src/SoftCopyright.Infrastructure --startup-project src/SoftCopyright.Api --output-dir Data/Migrations
dotnet ef database update --project src/SoftCopyright.Infrastructure --startup-project src/SoftCopyright.Api
```

> `dotnet ef` 只构建 API 项目。**新增迁移后必须再跑一次 `dotnet build`**，
> 否则测试 bin 里的旧 Infrastructure DLL 缺新迁移，会报 `Unknown column`。

```powershell
dotnet build     # 0 error / 0 warning

```

改了界面还要**实际渲染看一眼**（界面观感是本项目的验收标准之一）：

```powershell
dotnet run --project src/SoftCopyright.Desktop -- --demo --step Applicant --snapshot docs/screenshots/xxx.png
```

深浅两套主题都要看。

## 七、常见坑

### 1. 编译报文件被占用

```
error MSB3021: 无法将文件 …SoftCopyright.Desktop.exe 复制到 …：文件正由另一进程使用
```

先停掉正在运行的进程再编译：

```powershell
Get-Process | Where-Object { $_.ProcessName -like "SoftCopyright*" } | Stop-Process -Force
```

### 2. 客户端启动时卡死

**不要在 UI 线程上阻塞等待异步任务**。Avalonia 的同步上下文会让 `.GetAwaiter().GetResult()` 死锁。
引擎启动必须放在 Avalonia 初始化**之前**：

- 桌面端：`Program.Main` → `AppBootstrap.PrepareEngine(args)`
- Android：`MainActivity.OnCreate` 的 `base.OnCreate` 之前

切页刷新用 `Dispatcher.UIThread.Post`，不要 `GetAwaiter().GetResult()`。

### 3. 后台任务报 `no such table: BackgroundJobs`

**先迁移数据库，再启动后台任务**。`BackgroundJobWorker` 一上来就查任务表，库还没迁移就会炸。
正确顺序在 `DesktopEngine.StartAsync` 里：迁移 → 建账号 → `host.StartAsync()`。

### 4. Android 工程还原失败（找不到 Mono 运行时包）

不要把 `net10.0` 和 `net10.0-android` 放进**同一个工程**做多目标：还原会去要
`Microsoft.NETCore.App.Runtime.Mono.win-x64`（这个包根本不存在）。所以移动端是**独立工程**，
也**不在解决方案里**（避免没装 android 工作负载的机器编译失败），用 `./scripts/build-mobile.ps1` 单独构建。

### 5. 新克隆后 EF 迁移目录是空的

`.gitignore` 的 `data/` 没锚定到根目录时，`src/**/Data` 会被一起忽略。规则应该是 `/data/` 而不是 `data/`。

### 6. 改了材料规则但材料没变

材料规则有版本号（`MaterialRules.Version`）。确认内容哈希把规则版本算进去了，
改了规则会正确地让下游确认失效——这是预期行为，不是 bug。

## 八、新增一个平台

以 iOS 为例：

1. 装工作负载：`dotnet workload install ios`（**必须在 macOS 上**才能出安装包）
2. 照着 `src/SoftCopyright.Mobile` 建一个 `src/SoftCopyright.Ios`（`net10.0-ios` + `Avalonia.iOS`）
3. 界面**不用重写**：引用 `SoftCopyright.Client`，在 `App.OnFrameworkInitializationCompleted` 里走
   `ISingleViewApplicationLifetime.MainView = new ShellView { … }` 分支
4. 用 `./scripts/publish-desktop.ps1 -Platform macos` 或 `dotnet publish -r osx-arm64` 出包

**界面永远只有一份**（`SoftCopyright.Client/Views`）。不要为新平台另写一套界面——
窄屏适配靠 `ShellViewModel.IsCompact` + `WrapPanel` 流式布局自动完成。

鸿蒙是例外：鸿蒙 NEXT 没有 .NET 运行时，也装不了 Android APK，真要做只能另起 ArkTS 工程重写引擎。

## 九、提交与推送

```powershell
git add -A
git commit -m "feat(模块): 一句话说明这次改了什么、为什么"
git -c http.sslBackend=openssl -c http.version=HTTP/1.1 push origin main
```

> 若 `git push` 报 `Recv failure: Connection was reset` 或 `schannel: failed to receive handshake`，
> 加 `-c http.sslBackend=openssl -c http.version=HTTP/1.1` 重试（某些网络环境�� schannel 有问题）。

**红线**（详见 [`AGENTS.md`](../AGENTS.md)）：绝不执行被导入仓库中的代码；不生成或改写登记用源代码；
不把 AI 推断当法律事实；不宣称保证登记通过；不把源码正文与密钥写进日志。
